## 1. 用語と入力

### 1.1 判定の入力（ボールのイベント）

| イベント | 内容 | 主な属性 |
|---|---|---|
| `Hit` | ラケットでボールを打った | 打者、時刻、打点、ショットの種類（サーブか） |
| `Whiff` | 空振り（サーブ中のみ意味がある） | 打者 |
| `NetCross` | ネットの面（X = 0）を越えた | 時刻、位置、向き |
| `NetTouch` | ネット本体・白帯・ストラップに触れた | 部位、越えたか |
| `PostHit` | ネットポスト／シングルススティックに当たった | 種類 |
| `Bounce` | 地面に接地した | 位置（コート局所）、バウンド回数、どちら側か |
| `BodyHit` | ボールが選手の体（ラケット以外）に触れた | 選手 |
| `FixtureHit` | 恒久施設に当たった | 施設の種類 |
| `PlayerNetContact` | 選手がネットに触れた／相手コートに入った | 選手 |
| `FootFault` | フットフォールト（C 要件） | 選手 |
| `TossCaught` | トスをキャッチした | — |

### 1.2 判定の内部状態（1 ポイントの間）

| 状態 | 内容 |
|---|---|
| `Phase` | `Serve1`／`Serve2`／`Rally`／`Ended` |
| `Server`、`Receiver` | 選手の番号（0/1） |
| `ServeSide` | `Deuce`／`Ad` |
| `LastHitter` | 最後に打った選手 |
| `BouncesSinceHit` | 最後の打球からのバウンド回数 |
| `FirstBounceGood` | 最後の打球の最初のバウンドが、正しい区域に入ったか |
| `NetTouchedThisFlight` | 最後の打球の後にネットに触れたか |
| `CrossedNetThisFlight` | 最後の打球の後にネットを越えたか |
| `bNoLet` | No-Let ルール |

**正しい区域**：サーブのときは、対角のサービスボックス（ライン込み）。ラリーのときは、打者の相手側のシングルスコート（ライン込み）。

### 1.3 判定の出力

| 出力 | 内容 |
|---|---|
| `Continue` | 判定なし（続ける） |
| `Fault` | フォルト（`Serve1` なら `Serve2` へ、`Serve2` ならダブルフォルトで失点） |
| `Let` | サービスレット（同じサーブを打ち直す。それまでのフォルトは残る） |
| `Replay` | ポイントのやり直し（第 1 サーブから） |
| `PointWon(Winner, Reason, Rule)` | ポイントの終了。勝者・理由のコード・条番号 |

## 3. サーブの判定表

前提：`Phase` が `Serve1` か `Serve2`。サーバーが S、レシーバーが R。

| ID | 条件（起きた順） | 判定 | 条番号 |
|---|---|---|---|
| S01 | `TossCaught` | 判定なし（トスのやり直し。フォルトではない） | 19 Case 1 |
| S02 | `Whiff`（サーバーが空振り） | Fault | 19b |
| S03 | `FootFault`（有効時） | Fault | 18 |
| S04 | 打球後、地面に落ちる前に `BodyHit(S)` | Fault | 19d |
| S05 | 地面に落ちる前に `PostHit`（ポスト・スティック）または `FixtureHit` | Fault（その後に正しい区域に入っても Fault） | 19c、19 Case 2 |
| S06 | `NetTouch` → 越える → 最初の `Bounce` が正しいボックス | **Let**（`bNoLet` なら S10 と同じ扱い） | 22a |
| S07 | `NetTouch` → 越える → 地面に落ちる前に `BodyHit(R)` またはレシーバーが打つ | **Let**（`bNoLet` なら S11・S12 と同じ扱い） | 22a |
| S08 | `NetTouch` → 越えない（S の側に落ちる） | Fault | 19・17 |
| S09 | `NetTouch` → 越える → 最初の `Bounce` が正しいボックスの外 | Fault | 17 |
| S10 | ネットに触れず、最初の `Bounce` が正しいボックス | サーブ成功 → `Rally` へ（`LastHitter = S`、`BouncesSinceHit = 1`、`FirstBounceGood = true`） | 17 |
| S11 | ネットに触れず、地面に落ちる前に `BodyHit(R)` | `PointWon(S, ServeHitReceiver)` | 24 Case 7 |
| S12 | ネットに触れず、地面に落ちる前にレシーバーが打った | `PointWon(S, ReceiverVolleyedServe)` | 24e |
| S13 | ネットに触れず、最初の `Bounce` が正しいボックスの外（自コート・別のボックス・アウト） | Fault | 17 |
| S14 | サーブ中に `PlayerNetContact(S)`（インプレー中） | `PointWon(R, NetContact)`（Case 1：サーブがフォルトになる前ならサーバーの失点） | 24g、24 Case 1・2 |
| S15 | サーブがすでにフォルト（正しくない区域に落ちた）後の `PlayerNetContact` | Fault のまま（失点ではない） | 24 Case 2 |
| S16 | レシーバーの準備ができていない状態で打った（オンラインでのみ使う） | Let | 21、22b |

**Fault の後の処理**：`Serve1` → `Serve2`（同じサイドから）。`Serve2` → `PointWon(R, DoubleFault)`。
**Let の後の処理**：同じサーブ（`Serve1` なら第 1 サーブ、`Serve2` なら第 2 サーブ）を打ち直す。

## 4. ラリーの判定表

前提：`Phase = Rally`。最後に打った選手を H、相手を O とする。

| ID | 条件 | 判定 | 条番号 |
|---|---|---|---|
| R01 | H が打った後、`NetTouch` → 越える | Continue（有効） | 25a |
| R02 | H が打った後、`NetTouch` → 越えずに H の側で `Bounce` | `PointWon(O, NetError)` | 24c |
| R03 | H が打った後、越えずに H の側で `Bounce`（ネットに触れていない。例：自分のコートに打ち込んだ） | `PointWon(O, NetError)` | 24c |
| R04 | 越えた後、最初の `Bounce` が O 側のシングルスコート（ライン込み） | Continue（`FirstBounceGood = true`） | 12 |
| R05 | 越えた後、最初の `Bounce` が O 側のシングルスコートの外 | `PointWon(O, OutLong` または `OutWide)` | 24c |
| R06 | バウンドの前に `FixtureHit` | `PointWon(O, FixtureBeforeBounce)` | 24d、13 |
| R07 | `FirstBounceGood` の後、O が打つ前に `FixtureHit` | `PointWon(H, FixtureAfterGoodBounce)` | 13 |
| R08 | `FirstBounceGood` の後、O が打つ前に 2 回目の `Bounce` | `PointWon(H, Winner` または `DoubleBounce)`（O がラケットで触れていなければ `Winner`） | 24b |
| R09 | バウンドの前に `BodyHit(O)`（コートの外に立っていても、アウトになる球でも） | `PointWon(H, BodyHit)` | 24i、24 Case 8 |
| R10 | バウンドの後に `BodyHit(O)` | `PointWon(H, BodyHit)` | 24i |
| R11 | H が打った後に `BodyHit(H)` | `PointWon(O, BodyHit)` | 24i |
| R12 | O が、ボールがネットを越える前に打った（打点が H の側） | `PointWon(H, HitBeforeNet)` | 24h |
| R13 | O が打った（R04 の後、2 回目のバウンドの前、またはノーバウンド） | 打者の交代：`LastHitter = O`、各フラグをリセット | 25 |
| R14 | `PostHit`（スティック・ポスト）の後、越えて O 側のコートにバウンド | Continue（有効） | 25a・c |
| R15 | ポストの外側を回って（\|y\| > ポストの位置）O 側のコートにバウンド | Continue（有効。ネットの高さより低くてもよい） | 25c |
| R16 | スティックとポストの隙間を、コードの下を何にも触れずに通って、O 側のコートにバウンド | Continue（有効） | 25d |
| R17 | `PlayerNetContact(X)`（X はどちらか） | `PointWon(X の相手, NetContact)` | 24g |
| R18 | バウンドしたボールが、スピンや風で H の側へ戻った。O はネット越しに打ってよい | O の打球を有効とする（O が H の側に触れなければ） | 25b |
| R19 | O が正しい区域の外（コートの外）でノーバウンドで打った | 通常の打球として続ける（アウトの主張は通らない） | 24 Case 8 |

**勝者の分類**（統計用）：

- R08 で、O がラケットで一度も触れていない → `Winner`（H のウィナー）
- R08 で、O が触れたが返せなかった（空振りではなく、当たったが自分のコートに落ちた等）→ R02・R03 として O のミス
- R02・R03・R05 → H のミス。強制されたミスか凡ミスかは、統計の規則で判定する

## 5. スコアの規則

### 5.1 ゲーム（標準）

```
入力：ポイントの勝者 w（0/1）
P[w] += 1
if 標準ゲーム:
    if No-Ad かつ P[0] == 3 かつ P[1] == 3 → 次のポイントが決勝ポイント（レシーバーがサイドを選ぶ）
    if P[w] >= 4 かつ P[w] − P[1−w] >= 2 → ゲームの勝ち
    if No-Ad かつ P[w] == 4 かつ P[1−w] == 3 → ゲームの勝ち
```

| 表示 | 条件（サーバーのスコアを先に表示） |
|---|---|
| Love / 15 / 30 / 40 | P = 0 / 1 / 2 / 3 |
| Deuce | P[0] = P[1] ≥ 3 |
| Advantage（サーバー／レシーバー） | 両方 ≥ 3 で、差が 1 |
| Game | 上の勝ちの条件 |
| 決勝ポイント（No-Ad） | 3-3 |

### 5.2 タイブレーク

```
TBTarget = 7（通常）／10（Match TB 10、Final Set TB 10）／5（Short Set TB）
if P[w] >= TBTarget かつ P[w] − P[1−w] >= 2 → タイブレークの勝ち（ゲームとセット）
Short Set TB の場合：4-4 で決勝ポイント（2 点差は不要）
```

| 項目 | 規則 |
|---|---|
| サーブ順 | 第 1 ポイント：サーブ番の選手。以降、2 ポイントずつ交代（ポイントの合計 n に対して、サーバー = (n + 1) / 2 の偶奇で決める） |
| サーブ位置 | 第 1 ポイントはデュースサイド。以降、ポイントごとに交互（合計ポイントが偶数ならデュース） |
| エンドチェンジ | 6 ポイントごと（代替方式：第 1 ポイントの後、以降 4 ポイントごと。Short Set TB は最初の 4 ポイントの後だけ） |
| 次のセット | タイブレークで最初にサーブした選手は、次のセットの第 1 ゲームでレシーバーになる |
| ボール交換 | タイブレークの開始時には行わない（次のセットの第 2 ゲームへ延期） |
| 数え方 | タイブレークは 1 ゲームと数える（エンドチェンジ、ボール交換） |

### 5.3 セット

| 方式 | 規則 |
|---|---|
| Tie-break Set | G[w] ≥ 6 かつ差 ≥ 2 でセットの勝ち。6-6 でタイブレーク（7 点） |
| Advantage Set | G[w] ≥ 6 かつ差 ≥ 2（タイブレークなし） |
| Short Set | G[w] ≥ 4 かつ差 ≥ 2。4-4（設定で 3-3）でタイブレーク（7 点、または Short Set TB 5 点） |

### 5.4 マッチと最終セット

```cpp
enum class EFinalSetMode : uint8
{
    TieBreak7,          // 通常のタイブレークセット（6-6 で 7 点）
    Advantage,          // アドバンテージセット（タイブレークなし）
    TieBreak10At6All,   // 6-6 で 10 点タイブレーク（グランドスラム方式）
    MatchTieBreak7,     // 最終セットの代わりに 7 点のマッチタイブレーク
    MatchTieBreak10,    // 最終セットの代わりに 10 点のマッチタイブレーク
};
```

- 3 セットマッチ：2 セット先取。5 セットマッチ：3 セット先取
- マッチタイブレーク（最終セットの代わり）：セットオール（5 セットなら 2-2）で開始する。サーブ順は続ける。開始前にセットブレイク（120 秒）。ボールは替えない

### 5.5 サーブとエンドの順序

| 規則 | 内容 |
|---|---|
| 最初のサーバー | トスで決める（選択の規則は Rule 9） |
| ゲームごと | サーバーとレシーバーが入れ替わる |
| タイブレーク | §5.2 |
| 標準ゲームのサーブ位置 | ゲームの合計ポイントが偶数ならデュースサイド、奇数ならアドサイド（No-Ad の決勝ポイントは、レシーバーが選ぶ） |
| エンドチェンジ | 各セットの奇数ゲーム（1、3、5…）が終わったとき |
| セットの終わり | エンドを替える。ただし**そのセットの合計ゲーム数が偶数なら替えず、次のセットの第 1 ゲームの後に替える** |
| 休憩 | 奇数ゲームの後 90 秒。ただし**各セットの第 1 ゲームの後とタイブレーク中は休憩なし**。セットの終わりは 120 秒 |

### 5.6 局面

| 局面 | 条件 |
|---|---|
| ゲームポイント | 次のポイントを取ればゲームを取る |
| ブレークポイント | レシーバーのゲームポイント |
| セットポイント | 次のポイントを取ればセットを取る |
| マッチポイント | 次のポイントを取ればマッチを取る |
| 決勝ポイント | No-Ad の 3-3、Short Set TB の 4-4 |

## 6. 時間とボール交換

| 項目 | 規則 | 設定 |
|---|---|---|
| ポイント間 | 25 秒（ポイントが終わってからサーブを打つまで） | 実時間／スキップ可（既定）／なし |
| エンドチェンジ | 90 秒（第 1 ゲームの後とタイブレーク中はなし） | 同上 |
| セットブレイク | 120 秒 | 同上 |
| 時間の違反（AI とオンライン） | 1 回目は警告、2 回目以降はサーバーならフォルト、レシーバーなら失点（大会の規定に従う。ゲームでは既定でオフ） | オン／オフ |
| ボール交換 | 7 ゲームまたは 9 ゲームごと（最初は 2 ゲーム早く）、またはセットの始め | なし（既定）／7・9 ゲーム／セットごと |
