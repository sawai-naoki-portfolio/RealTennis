## 1. 操作の考え方

1. **左手で足、右手でショット**。移動と狙いは同じ左スティック（ボタンを押している間の入力を「狙い」として扱う）
2. **押して溜め、離して打つ**。押した瞬間にストロークを予約し（テイクバックが始まる）、離した瞬間をタイミングとして評価する
3. **球種はボタン、強弱は修飾キー**。トリガーで「強打」と「コントロール」を選ぶ
4. **入力は即座に受け付け、体の動きは人間らしく**。入力の遅延は作らない。重さはアニメと加速の曲線で表現する

修飾キーとボタンの組み合わせは、Input Action の Chorded Trigger を使わず、`UTennisShotInputComponent` で判定する（押した順番に依存しないようにするため）。

- 球種のボタンは、トリガーを付けず（既定の Down）、押した瞬間を `Started`、離した瞬間を `Completed` で受ける。1 つの Action に Pressed と Released のトリガーを両方付けると、どちらも `Triggered` になって区別できないため
- 球種は「押しているボタン」と「技の修飾（`IA_Mod_Technique`）を押しているか」の組み合わせで決まる。溜めの間に修飾を押す・離すと球種を決め直し、離した瞬間の組み合わせで確定する（§4.1）
- ボタンと球種の対応はデータ（`UTennisInputSettings`、Project Settings → Tennis Input）に置く。ラリー：トップスピン → Topspin、フラット → Flat、スライス → Slice（修飾つきは Drop）、ロブ → Lob（修飾つきは SliceLob）。サーブの対応（§5）は別の表にする

## 4. ストロークの入力とタイミング

### 4.1 流れ

```
[相手のインパクト]
   │  （予約の受付開始。これより前の押下も保持する：入力バッファ 最大 1.2 s）
   ▼
押す ─▶ 予約：球種が決まる。打点の候補を探し、ストロークを選んでテイクバックを始める
   │       溜め Charge が 0 → 1（ChargeTime はストロークごと。既定 0.70 s）
   │       押している間、左スティックが狙いになる（移動は自動の打点への接近に切り替わる。§4.5）
   ▼
離す ─▶ 時刻 t_rel を記録。Δt = t_rel − t*（t* ＝ 理想の離す時刻）
   │       狙い・溜め・修飾キーをここで確定する
   ▼
[インパクト（AnimNotify）] ─▶ 品質の計算 → 誤差 → ソルバ → 打球
```

- **理想の離す時刻** `t* = T_impact − ReleaseLeadTime`。`ReleaseLeadTime` はストロークのデータで決める（下表）。スイングの開始から当たるまでの時間に相当する
- **離さなかった場合**：インパクトの時点でまだ押していたら、そこで自動的に離したことにする。判定は `t* + W_late` に離したもの（Late の端）、溜めは最大。`W_late` は Early／Late の窓の端（§4.2。0.200 s、カジュアルは 0.240 s）。`ReleaseLeadTime`（下表、0.15 s 以下）は `W_late` より短いので、`t* + W_late` はいつもインパクトより後になる。ショットはインパクトで決まるので、そこで決める（利用者の判断、2026-11-14）。その後に離しても何も起きない
- **早すぎる離し**（Δt < −0.20 s）：ストロークは予定どおり振るが、品質が最低（0.1）になる。プレイヤーには「早すぎ」と表示する
- 予約後に別の球種のボタンを押すと、`t* − 0.25 s` までなら球種を変えられる（それ以降は無視する）

| ストローク | ReleaseLeadTime（s） | ChargeTime（s） |
|---|---|---|
| フォアハンド（ドライブ） | 0.12 | 0.70 |
| バックハンド（両手） | 0.13 | 0.75 |
| バックハンド（片手） | 0.14 | 0.80 |
| スライス | 0.10 | 0.60 |
| ロブ | 0.11 | 0.55 |
| ドロップ | 0.09 | 0.40 |
| ボレー | 0.06 | 0.30 |
| ハーフボレー | 0.07 | 0.30 |
| スマッシュ | 0.15 | 0.60 |
| ストレッチ・スライディング | 0.10 | 0.40 |

### 4.2 タイミングの判定

| 判定 | シミュレーション | スタンダード | カジュアル | 品質への係数 q_t |
|---|---|---|---|---|
| Perfect | \|Δt\| ≤ 0.030 s | ≤ 0.040 s | ≤ 0.060 s | 1.00 |
| Good | ≤ 0.070 s | ≤ 0.090 s | ≤ 0.130 s | 1.00 → 0.75（線形） |
| Early / Late | ≤ 0.200 s | ≤ 0.200 s | ≤ 0.240 s | 0.75 → 0.30（線形） |
| 大きく早い／遅い | それ以上 | それ以上 | それ以上 | 0.10 |

- **強打**（RT）を押していると、窓の幅が ×0.8 になる
- **来た球の速さ**で窓を狭める：`W ×= clamp(1 − 0.006·(v_in − 25), 0.75, 1.0)`（v_in は m/s）
- Early／Late のときの狙いの流れ：`ΔAim_side = sign · k_pull · (|Δt| − W_good)`、`k_pull = 8 m/s`。向き（sign）は、Early で「体の前で打つ → 引っ張る方向（右利きのフォアならクロス）」、Late で「流す方向」。利き手とフォア／バックで反転させる

### 4.3 狙い（ゲームパッド）

ショットのボタンを押している間の左スティック `(sx, sy)`（自分から見て上が相手側。奥側のコートの選手は反転する）を、相手コートの目標点 `(depth, side)` に変換する。depth はネットからの距離（m）、side は中心線からの距離（m）。

```
depth = sy ≥ 0 ? lerp(9.0, 10.8, sy) : lerp(9.0, 5.0, −sy)
side  = sx · (depth ≥ 8.0 ? 3.4 : 3.8)
```

- スティックがニュートラルのとき：中央の深め（9.0 m, 0）
- 上に倒す：ベースラインの手前 1.1 m まで深く
- 下に倒す：短く（ショートクロス・アングルは「下＋横」）
- 安全マージン（アシスト）：目標点をラインから `margin` m 内側に入れる
- **ドロップ**：depth = lerp(2.5, 4.0, sy+1/2)、side = sx · 3.0
- **ロブ**：depth = lerp(9.5, 11.0, max(sy, 0))
- 最終的な目標点は、離した瞬間のスティックの値で決める

**マウスで狙う**場合：カーソルが指すコート上の点を、そのまま目標点にする（上の式は使わない）。σ は同じ。

### 4.4 修飾キー（トリガー）

| 修飾 | 目標の球速 | σ | 窓 | 回転 |
|---|---|---|---|---|
| なし | 溜めで決まる | ×1.0 | ×1.0 | 球種の既定 |
| 強打（RT = 1.0） | ×1.15 | ×1.30 | ×0.80 | トップスピンは −15% |
| コントロール（LT = 1.0） | ×0.80 | ×0.80 | ×1.10 | トップスピンは +10% |

トリガーはアナログで、押し込み量 0〜1 で線形に補間する。両方を押したときは打ち消し合う（差を使う）。

### 4.5 ボタンを押している間の移動

- ボタンを押した瞬間に、打点の候補（[ストローク詳細](../04_DetailedDesign/03_Player_Movement_Stroke_Detail.md) §3）が決まる。キャラクターは**その打点に入るための目標位置へ自動で移動する**（スティックは狙いに使うため）
- 自動の移動の速さは、選手の能力値どおり（速くはならない）。間に合わないときは、ストレッチ／ダイブのストロークになる
- **アシスト「シミュレーション」では、押している間もスティックで移動を続けられる設定を選べる**（狙いは押した瞬間のスティックの向きで固定する。「移動優先」モード）

### 4.6 スプリットステップ

- 自動（スタンダード・カジュアル）：相手のインパクトの 0.10 s 前に跳び始め、インパクトの直後に着地する（毎回「良い」）
- 手動（シミュレーション）：L3／Q を押す。**着地の時刻が相手のインパクト ±0.08 s なら「良い」**。良いと 0.3 秒間の初動ブースト（加速 ×1.5）。早すぎ・遅すぎはブーストなし。押さなければスプリットステップなし（初動 ×0.85）

## 5. サーブの入力

```
[準備]  左スティックで立ち位置（センターマークからシングルスのサイドラインの延長まで）
   │
   ▼
球種ボタンを押す ─▶ トス（物理で上げる。頂点 = 打点の理想の高さ + 0.05 m）
   │                トスの左右・前後のぶれ：σ_toss = 0.05〜0.15 m（サーブの精度の能力値による）
   │                押している間：溜め、左スティックで狙い（サービスボックス内のマーカー）
   │                LB：トスのやり直し（キャッチ。フォルトではない）
   ▼
離す ─▶ 打点の高さとトスの位置から品質を計算し、インパクトのアニメへ
```

| 項目 | 内容 |
|---|---|
| 理想の離す時刻 | トスの頂点から 0.07 s 後（落ち始め）。理想のインパクトは、その後ボールが下降して頂点より 0.05 m 下に達したとき（DD-03 §10） |
| 判定 | Perfect：±0.04 s、Good：±0.09 s、それ以上は Early／Late（アシストで変わらない。サーブは練習で上達させる） |
| 早すぎ | 打点が低い（ネットのリスク）。遅すぎ：打点が下がる＋体が流れる |
| トスのぶれ | 横に 0.1 m ずれると、品質 −0.15。プレイヤーはトスを見てやり直せる |
| 溜め | 0 → 1 を 0.9 s。速さ：フラット 45 → 64 m/s、スライス 40 → 54 m/s、キック 35 → 46 m/s（能力値で補正） |
| 第 2 サーブ | 同じ操作。HUD に「2nd」と表示し、溜めの上限を 90% にする（設定でオフ） |
| 狙い | 左スティックで、サービスボックス内のワイド／ボディ／センター（T）を連続的に選ぶ。深さは上下 |
| 回転軸 | 球種ごとに既定の軸。スティックの横の入力で、軸を ±15° 傾けられる（スライスの曲がりを強める、など） |

## 6. レシーブ

- 準備中は、ベースラインの付近だけ左右と前後に動ける（ベースラインの 4 m 後ろ〜1 m 前）
- サーブが打たれた後は、通常のラリーと同じ操作
- 使える時間が短い（約 0.55〜0.75 s）ので、**予約は相手のトス中から受け付ける**（入力バッファ）。球種を押しておけば、到達した打点に応じてストロークを選ぶ
- 準備の時間が足りないときは、自動的に**ブロックリターン**（テイクバックの小さいストローク）を選ぶ。品質の上限は 0.8

## 8. タッチ操作（スマートフォン）

### 8.1 共通の方針

1. **どの方式でも、最後は同じ `FShotIntent`** を作る（FR-INP-010）。タイミング・狙い・溜めの評価は §4 と同じ式を使う
2. タッチでは、指でコートが隠れることと、触覚で位置が分からないことが問題になる。そこで、**移動のアシストを強めた「タッチ向け」プリセット**を既定にする（下表）
3. 方式は 2 つ用意し、設定で切り替える。どちらも左右反転（左利き用）ができる

| 項目 | タッチ向けプリセット（既定） | 備考 |
|---|---|---|
| 移動のアシスト | 50%（ボタン方式）／80%（スワイプ方式） | スワイプ方式は、基本的に自動で打点へ向かう |
| タイミングの窓 | スタンダードと同じ | 窓は広げない（指を離す時刻は正確に測れる） |
| スプリットステップ | 自動 | |
| 着地点マーカー | 短く表示 | |
| 狙いの安全マージン | 0.5 m | |

### 8.2 ボタン方式

```
 ┌───────────────────────────────────────────────────────────────┐
 │ [||]                        スコア                    [カメラ] │
 │                                                               │
 │                       （コート：中継カメラ）                    │
 │                                                               │
 │                                              (Y ロブ)          │
 │   ╭───╮                              (X フラット) (B スライス)  │
```

| 操作 | 内容 |
|---|---|
| 左半分を触って動かす | 浮動の仮想スティック（触った点が中心）。半径 12 mm 相当で最大入力。指を離すと 0 |
| 球種ボタン（右下の 4 つ） | 押して溜め、離して打つ。**押している間は左のスティックが狙い** |
| ボタンから指を滑らせる | 球種ボタンを押したまま、別の球種ボタンへ指を滑らせると、§4.1 の規則どおり球種を変える |
| 「強打」ボタン | 押しながら球種ボタンを押すと強打（トリガーの 1.0 と同じ）。ダブルタップで切り替えの固定もできる |
| 「技」ボタン | ゲームパッドの RB と同じ（スライスでドロップ、ロブでスライスロブ） |
| サーブ | 球種ボタンを押すとトス、離すとインパクト。スティックで狙い。トス中に画面の上半分をタップするとトスのやり直し |
| ダッシュ | スティックを外周の外まで倒し続ける（半径の 1.3 倍以上） |

### 8.3 スワイプ方式

右半分（左利き用の設定では左半分）でのスワイプで、球種・狙い・タイミングをまとめて入力する。移動は、アシスト 80% で自動的に打点へ向かう（左半分の浮動スティックで修正できる）。

| 段階 | 指の動き | 決まるもの |
|---|---|---|
| ① 触れる | 右半分のどこかに指を置く | **予約**（ストロークを選び、テイクバックを始める）。溜めの開始 |
| ② 動かす | 置いたまま、方向と形を描く | **狙い**（向き）と**球種**（形）。長さは溜めに上乗せする |
| ③ 離す | 指を離す | **タイミング**（離した時刻 = §4.1 の t_rel） |

**形による球種の判別**（指の軌跡を 16 点に再サンプルし、テンプレートとの距離で判別する）：

| 形 | 球種 | 判別の条件（初期値） |
|---|---|---|
| まっすぐ上（相手のコートの方向） | フラット | 直線度 > 0.9、曲率が小さい |
| 上に向かって弧（終わりが上に反る） | トップスピン | 終わりの 30% の区間で、上向きに 20° 以上曲がる |
| 上に向かって弧（終わりが下に流れる）／下から上への「切る」動き | スライス | 終わりの 30% の区間で、下向きに 20° 以上曲がる |
| 大きく上に跳ね上げる（長い） | ロブ | 長さ > 画面の高さの 35%、かつ速度が遅い |
| 短く止める（タップに近い） | ドロップ | 長さ < 8 mm 相当、かつ「技」の修飾（右下の小さなボタンを押しながら） |
| タップ（ほとんど動かさない） | 直前の球種を繰り返す（設定でオフ） | 長さ < 4 mm 相当 |

| 項目 | 規則 |
|---|---|
| 狙いの向き | スワイプ全体の向き（始点 → 終点）を、§4.3 の `(sx, sy)` に変換する（上 = 深く、横 = 左右） |
| 狙いの深さ | スワイプの縦の長さを `sy` に足す（長いほど深い） |
| 溜め | 触れていた時間で §4.1 と同じく増える。長いスワイプは溜め +0.1 |
| 強打 | 速いスワイプ（指の速度 > 1,500 px/s 相当）で、強打の修飾 0.5 を加える |
| 判別の誤り | 判別の信頼度が低い場合は、ボタン方式と同じ既定の球種（トップスピン）にする。判別の結果は HUD に一瞬表示する |
| サーブ | 指を置く → トス。上にスワイプ → インパクト（離した時刻がタイミング）。スワイプの向きで狙い、形で球種（まっすぐ = フラット、右に曲がる = スライス、上に反る = キック。左利きは反転） |

**判別の検証**：開発者が描いた 1,000 本以上のスワイプのデータで、自動テスト（T-INP-020）を行い、正しく判別できる割合が 95% 以上であることを確認する。

### 8.4 タッチ入力の実装

| 項目 | 方針 |
|---|---|
| 入力の取り込み | UMG のタッチウィジェット（CommonUI のレイヤーの上）でタッチを受け、`UEnhancedInputLocalPlayerSubsystem::InjectInputForAction` で同じ Input Action（`IA_Move`、`IA_Shot_*` など）に流す。スワイプ方式は `UTennisSwipeRecognizer` で形を判別してから流す |
| 旧式の Touch Interface | 使わない（Enhanced Input と統合しにくい） |
| マルチタッチ | 最大 3 点（スティック、球種、修飾） |
| 時刻 | タッチのイベントの時刻（OS のタイムスタンプ）を使い、フレームの境目に丸めない（タイミングの判定の精度） |
| 入力機器の切り替え | CommonInput の現在の入力の種類（Touch／Gamepad／MouseAndKeyboard）が変わったら、HUD の案内とボタンの表示を切り替える |
