## 1. 方針

1. **AI はプレイヤーと同じ経路で打つ**：`FShotIntent` を作り、同じストローク・品質・誤差・ソルバを通る（FR-AI-001）。AI だけの正確な打球はない
2. **AI が見てよい情報**は、人間のプレイヤーが画面から読み取れる情報だけ：ボールの軌道（反応の遅れと誤差つき）、相手の位置と向き、相手のストロークの種類（構えで分かる）、スコア。**相手の入力（狙い・溜め）は見ない**
3. 強さの違いは、反応・予測の誤差・タイミングの誤差・判断（リスク）で作る。物理と能力値は同じ規則で効く

## 2. StateTree の構成（`ST_TennisAI`）

状態図は [ST-06](../03_UML/04_State_Diagrams.md)。

| 状態 | タスク | 終了の条件 |
|---|---|---|
| Wait | 構えて待つ | 試合の段階が変わった |
| Serve | `FSTT_TennisServe`：球種・狙い・溜めを選び、トス → 離す | サーブを打った |
| Rally / Recover | `FSTT_TennisRecover`：リカバリーの位置へ動く | 相手が打った |
| Rally / Perceive | 反応の遅れの間は、知覚した軌道を使わない | 反応時間が過ぎた |
| Rally / Intercept | `FSTT_TennisIntercept`：打点を選び、移動する | 打点の時刻 − 準備時間 |
| Rally / Strike | `FSTT_TennisChooseShot`：候補を評価し、意図を出して打つ | インパクト |
| NetPlay | `FSTT_TennisNetApproach`：ネットへ詰め、ボレーの構え | ロブで下げられた／ポイント終了 |
| PointEnd | リアクション | 次のポイント |

**評価器** `FSTE_TennisRallyContext` が毎フレーム、共有の文脈（`FTennisRallyContext`）を更新する：知覚した軌道、反応の準備の時刻、予測の誤差、相手の位置・体勢、局面。

## 3. 知覚

### 3.1 反応の遅れ

- 相手のインパクト（`OnBallLaunched`）から `ReactionTime`（難易度）の間、AI は新しい軌道を知らない（前の予測のまま、または構えで待つ）
- 反応時間に、局面とスタイルの補正を掛ける：`ReactionTime × (1 − 0.1 × 予測の能力値の偏差)`

### 3.2 予測の誤差

```
知覚の着地点 = 真の着地点 + n(t)
n(t) ~ N(0, σ_pred(t)²)（深さと横の 2 次元。時刻ごとに独立ではなく、ゆっくり変わる値として扱う）
σ_pred(t) = PredictionNoise0 × exp(−(t − t_ready) / 0.25) + 0.05      [m]
```

- 知覚した軌道は、真の軌道を着地点の誤差の分だけ平行移動したもの（形は同じ）。打点の探索はこの軌道で行う
- 時間が経つほど誤差が減るので、**難易度の低い AI は最初に間違った方向へ動き始め、途中で修正する**（人間らしく見える）

### 3.3 相手の読み（予測の能力値が高い AI）

- 相手の `OnStrokeStarted`（ストロークの種類・打点の位置・体の向き）から、相手の打ちそうなコースの事前分布を作る。`FTennisOpponentModel`（§7）の傾向と合わせて、**相手のインパクトの前に** 0.1〜0.2 m だけ先に動き始める
- 先読みの量は、難易度の `AnticipationWeight`（Easy 0 〜 Legend 0.6）

## 4. ショットの選択（`FSTT_TennisChooseShot`）

### 4.1 候補

| 種類 | 候補 |
|---|---|
| 狙い | 深さ 3 段（深い 10.3 m・中 8.5 m・浅い角度 5.5 m）× 横 5 段（±3.3・±1.7・0 m）＝ 15 点 |
| 球種 | Topspin・HeavyTopspin・Flat・Slice（打点と体勢で可能なもの）、＋ Lob（2 点）、＋ Drop（2 点） |
| 溜め | 平均 `MeanCharge`（難易度）±0.15 の 3 段 |

最大で約 15 × 4 × 3 + 12 = 192 候補。各候補はショット表（[DD-02 §9](02_ShotSystem_Detail.md)）を引くだけなので、合計 0.1 ms 程度。

### 4.2 評価

各候補 c について、自分の σ（品質の予測値から計算）を使って：

```
P_out(c)   = 1 − Φ(margin_depth / σ_d) · Φ(margin_side / σ_s)        … 目標点からラインまでの余裕
P_net(c)   = 1 − Φ(netClearance(c) / (σ_d · k_net))                   … k_net = 0.35（深さの誤差がネットの高さに与える影響）
P_err(c)   = 1 − (1 − P_out)(1 − P_net)
t_arrive   = c の着地点（または相手の打点の候補）に球が来る時刻
t_opp      = 相手が c の打点に入るまでの時間（相手の位置・速さから）
P_win(c)   = σ_logistic((t_opp − t_arrive − 0.1) / 0.12)                … 相手が間に合わない確率（ウィナー）
Pressure(c)= 相手を走らせる距離 / 6 m（0〜1）＋ 球速・回転による難しさ
U(c) = w_win·P_win + w_press·Pressure − w_err·P_err·(1 + 局面の重さ) + Style(c)
```

| 重み | 既定 | 調整 |
|---|---|---|
| w_win | 1.0 | `RiskAppetite` で ×(0.6〜1.4) |
| w_press | 0.6 | スタイル |
| w_err | 1.5 | `RiskAppetite` で ×(1.6〜0.7) |
| Style(c) | — | `UAIPlayStyleData` の球種の重み・ネットに出る傾向・ドロップの傾向 |

### 4.3 選び方

- `P(c) ∝ exp(U(c) / T)`（softmax）、温度 T = `SoftmaxTemperature`（Easy 0.35 〜 Legend 0.08）
- 選んだ候補の目標点に、AI の狙いのマージン（`AimMargin`）を足してから、`FShotIntent` を作る
- **離す時刻**：理想の時刻 + `N(0, TimingSigma)`。これでタイミングの誤差がプレイヤーと同じ式で効く

## 5. サーブ・リターン・ネットプレー

### 5.1 サーブ

| 局面 | 第 1 サーブ | 第 2 サーブ |
|---|---|---|
| 通常 | 球種：スタイルの比率（ビッグサーバーはフラット 60%）。コース：ワイド／ボディ／T を、相手のリターンの弱い側に寄せる | キック 70%・スライス 30%。マージン ×1.5、溜め ×0.85 |
| ブレークポイントを握られた | 確率重視（マージン ×1.2） | 同上（ダブルフォルトの率が上がりすぎないように） |
| 相手がリターンの位置を下げている | ワイドとボディの比率を上げる | — |

### 5.2 リターン

- 使える時間が短いので、選ぶ候補を減らす（深さ 2 段 × 横 3 段、球種は Topspin・Slice・Block）
- 速いサーブ（> 50 m/s）には、Block と Slice の重みを上げる

### 5.3 ネットプレー

| 条件 | 行動 |
|---|---|
| 相手の球が浅い（自分の打点がネットから 8 m 以内）かつ `NetApproachBias` が高い | アプローチショット（深い Slice／Topspin）を打って前へ |
| サーブ＆ボレーのスタイル | 第 1 サーブの 70%（第 2 サーブの 30%）で、サーブの後に前へ |
| ネットにいるとき | ボレーの候補（深さ・角度・ドロップボレー）。相手のロブには下がってスマッシュ、届かなければ追いかけてロブ／Slice で返す |

## 7. 相手のモデル（`FTennisOpponentModel`）

- 相手の打球の着地点を、相手の打点の位置（フォア／バック × 深さ 2 段）ごとに、3 × 3 の区画のヒストグラムとして数える（指数移動平均、半減期 20 打）
- 予測の能力値が高い AI は、このヒストグラムで知覚の誤差の平均（バイアス）を相手の傾向の方向に寄せる。最大 0.3 m（FR-AI-007）

## 8. ラバーバンド（任意。既定はオフ）

- 点差（ゲーム差）に応じて、反応時間を ±10% まで変える。リードしているときは遅く、負けているときは速く
- 設定でオン／オフ。オンでも「シミュレーション」のアシストでは無効にする

## 9. 調整の方法

1. AI 対 AI の自動対戦（[テスト計画 §6](../08_QA/01_Test_Plan.md)）で、Pro 対 Pro のリアリティ KPI を目標範囲に合わせる（ラリーの長さ・ミスの比率・サーブの確率）
2. 難易度ごとに、人間のプレイテストで勝率を確かめる（Easy：初心者が 70% 以上勝つ。Hard：上級者が 50〜65% 勝つ）
3. スタイルごとに、ネットに出る率・球種の比率が他のスタイルと区別できること（KPI の差）
