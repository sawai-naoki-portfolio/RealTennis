## 2. 移動（`UTennisMovementComponent`）

### 2.1 基本のパラメータ（能力値 50・スタミナ 100%）

| 量 | 値 | 能力値の写像（0 → 100） |
|---|---|---|
| 最高速度 | 5.5 m/s | スピード：4.8 → 6.2 m/s |
| 加速 | 8.0 m/s² | 加速：6.5 → 9.5 m/s² |
| 減速（ブレーキ） | 10.0 m/s² | 加速：8.5 → 11.5 m/s² |
| 方向転換 | 進行方向から 90° 以上変えると、その瞬間の速さの 35% を失う | — |
| ダッシュ | 最高速度 ×1.08、スタミナ消費 ×3 | — |
| 初動ブースト | スプリットステップが「良い」と、着地から 0.3 s の加速 ×1.5 | — |
| 後退 | 最高速度 ×0.75、加速 ×0.85 | — |
| フォロースルー中 | 最高速度 ×0.40（`UStrokeData::FollowThroughLock` の時間） | — |

> 根拠：RES-03 §2 の設計推定（人間の初動の加速 6〜9 m/s²）。既存設計の 25 m/s² は使わない（RES-05 指摘 3）。

### 2.2 計算の置き場所と規則

水平の速度は TennisSim の `TennisMovement::Step`（`TennisSim/Public/Movement/TennisMovement.h`。Engine に依存しない純粋な関数）で計算する。`UTennisMovementComponent` は `CalcVelocity` をオーバーライドしてこれを呼び、床・衝突・高さは CMC に任せる。テスト（T-MOVE-001〜003）は、固定の時間刻み（240 Hz）で純粋な関数を確かめる（2026-11-04 に、CMC の設定を毎フレーム反映する案から変えた。計算を 1 か所にし、テストと決定論を得るため）。

| 規則 | 内容 |
|---|---|
| 加速 | 入力の向きへ Accel で速める（初動ブースト中は ×1.5、後退は ×0.85）。速さは最高速度で頭打ち |
| 減速 | 入力がないとき、または最高速度を超えたとき（フォロースルーに入ったなど）は、Brake で 0 または最高速度まで減らす |
| 方向転換 | 入力の向きと速度の向きの角度が 90° を超えた瞬間に、速度を 0.65 倍にする。角度が 90° 以下に戻るまで、次の損失は起きない（1 回の方向転換につき 1 回） |
| 後退 | 入力の向きのうち、ネットから離れる成分が cos 45°（≈ 0.71）以上のとき。最高速度 ×0.75、加速 ×0.85 |
| ダッシュ・フォロースルー | 1 ステップの入力のフラグ。最高速度 ×1.08／×0.40（ダッシュのスタミナの消費は M6） |
| 入力 | 長さ 1 以下の 2 次元のベクトル（スティックの倒し具合）。長さが 1 を超えれば 1 に、数でなければ 0 にする。スティックと WASD の向きは**コートに対して**決める（上＝ネットの方向、右＝自分から見たコートの右。X > 0 の側の選手は反転する。[操作仕様 §4.3](../01_Specification/04_Controls_Specification.md) の狙いの写像と同じ向き）。`ATennisPlayerController` が、選手の側とコートの向きでワールドの向きに直し、ポーンに渡す（斜めの WASD も長さ 1 にする。コートが見つからないときはカメラの向きを使う）。2026-11-11 に「画面に対して（カメラの向き）」から変えた（利用者の判断）：中継カメラは選手の側へ最大 15° ほど回る（DD-07 §1.1）ので、画面に対する向きでは横の移動が斜めになる（PIE で、左の端から 10.6 m 横へ動くと前へ 0.9 m・5°） |
| 固定の刻み | モデルは 240 Hz（`TennisConst::SimDt`）のステップで進める（ボールと同じ刻み：ARCH-03 D-3）。`CalcVelocity` は、CMC の 1 回の移動の時間（フレーム、または CMC が分けた区間）と、カプセルの中心の今の位置を `TennisMovement::AdvanceFrame` に渡す。最後のステップのモデルの位置は「今の位置 − 前のフレームで先へ渡した分」とし、そこからステップを進め、**ステップごとに範囲に収める**（§2.4）。CMC には「最後のステップの位置 + 今の速度 × まだステップにしていない時間（範囲に収める）」へ動く速度を渡す。そのため、CMC が動かした位置は、フレームの分け方（240 で割り切れないフレームを含む）によらず、範囲に収めながら同じ数だけステップしたモデルの位置と合う（T-MOVE-005）。CMC の速度は読み戻さない（CMC の `Velocity` に書いても、モデルには届かない。ポイントの開始で選手を置き直すときは、モデルの状態も戻す手段を作る）。CMC の速度は、そのフレームで動く速度でフレームの分け方で変わるので、打点の探索（§4）などは**モデルの速度**（`GetMoveState`）を読む。CMC が動けなかった分（衝突・瞬間移動）は、今の位置を起点にするので、追いつこうとせずにそこから続ける（選手が動ける範囲の中に、コリジョンのある物はない：練習コートの小物とスタジアムはコリジョンなし。ART-03 §5）。入力は、そのフレームのすべてのステップに使う。時間の倍率はボールと同じ（`tennis.TimeScale`）。刻みの累積はボールとは別に持つ（ボールの時計は飛んでいる間だけ進むため）。ボールは 1 フレームを 0.1 s で切り詰め、CMC は 0.05 s ごとに分けて最大 8 回進めるので、0.1 s より長い引っかかりの後だけ、選手とボールの進んだ時間が食い違う（ストロークの時刻合わせはボールの時刻で決め直すので、続かない）。CMC のクライアント予測（DD-06）では、この累積・先へ渡した分・自動移動の目標（§2.3。入力はステップの中で作り、CMC の入力としては送らない：DD-06 §8 の「入力ベクトルとして送る」と違う）・フォロースルーの制限（`Modifiers`。§6.6）が CMC の保存する移動の状態の外にある。オンライン（v1.1）を作るときに見直す |

| CMC の設定（`UTennisMovementComponent` が持つ） | 値 | 備考 |
|---|---|---|
| `RotationRate` | Yaw 720°/s | 体の向きはアニメ（Orientation Warping）で補う |
| `bOrientRotationToMovement` | false | 選手は基本的にネットの方向を向く。ストローク中は打球方向 |

### 2.3 自動移動（打点への接近）とアシスト

- ストロークを予約した後（打点の候補が見つかったとき）は、`UTennisMovementComponent::SetAutoMoveTarget(目標位置, 残りの時間, 止まっていたい時間)` で打点に入る位置へ向かう。目標位置は、ストロークが決まった後に選び直した打点（§6.2）の体の目標（コート局所、カプセルの中心。`UTennisStrokeComponent::PlayStroke` が置く）、残りの時間は「選び直した打点の時刻 − ボールの今の時刻」、止まっていたい時間は探索の余裕の満点（`FReachParams::FullMargin`、0.15 s）。インパクトで止め（§6.6）、ストロークが終わる・入力が取り消されても `ClearAutoMoveTarget`。自動移動の間は、スティックの入力を使わない（ボタンを押し続けても、インパクトで止まり、RecoverStart でストロークが終わる。押したままインパクトが来たら、入力は自動で離した扱いで確定する：§6.6）
- 入力（`TennisMovement::AutoMoveInput`）は、移動のモデルの**ステップごと**に決める（フレームの分け方によらない：§2.2）。向きは `normalize(目標 − 現在)`。速さは、止まっていたい時間の前に着く最小の速さ u：止まった状態から加速 → u → 減速で、距離を使える時間 T（残り − 止まっていたい時間）で進む u（u²·C − u·T + 距離 = 0 の小さい解、C = 1/(2·加速) + 1/(2·減速)。後退は後退の最高速度と加速）。止まった状態から見積もるので、実際は少し早く着いて構える。解がない（間に合わない）・時刻を過ぎたときは最高速度。どの場合も、目標で止まれる速さ √(2·減速·距離) を超えない。目標から 2 cm 以内なら止まる（T-MOVE-006）
- 止まる位置で 0.15 s 前に静止できると、体勢のペナルティなし（点数：§4.3）
- **移動のアシスト**（予約前）：`入力 = normalize(lerp(スティック, 理想打点への向き, AssistWeight))`。AssistWeight はアシストの設定（0 / 0.15 / 0.35、タッチ 0.5 / 0.8）

### 2.4 コートの範囲

- 選手の移動範囲：自分の側の X（ネットから 0.15 m 手前まで）〜 ベースラインの後ろ 6 m。横はダブルスのサイドラインの外 3.5 m まで
- ネットに 0.15 m 以内に近づくと止まる（FR-MOVE-006）。止まりきれずに触れた場合だけ `PlayerNetContact`（ルールの判定）
- 0.15 m は体（カプセルの表面、半径 0.30 m）からの距離。カプセルの中心は |X| ≥ 0.45 m に収める。範囲の端に当たったら、その向きの速度の成分を 0 にする（`TennisMovement::ClampToArea`）。収めるのは移動のモデルのステップの中（§2.2）で、範囲の外から始めても、最初のフレームで中に戻す。root motion で動く間（CMC の既定の計算）は収めないが、ストロークは root motion を使わない（§6.2）

## 4. 打点の探索（`UTennisReachComponent`）

アルゴリズムは [ACT-03](../03_UML/05_Activity_Diagrams.md)。

### 4.1 到達時間

距離 d、最高速度 v、加速 a、ブーストの残り時間 b、ブーストの倍率 k のとき：

```
a_eff = a × (b > 0 ? k : 1)            … ブーストの区間は加速を上げる（区間をまたぐ場合は 2 区間に分けて計算）
d ≤ v²/(2a_eff) なら t = √(2d / a_eff)
そうでなければ   t = v / a_eff + (d − v²/(2a_eff)) / v
```

現在の速度の成分（目標方向の初速）も考慮する（初速 u がある場合の等加速度の式を使う）。

### 4.2 体の位置

```
体の目標位置 = 打点 − 打球方向に直交する横方向 × 横の距離 − 打球方向 × 前の距離
横の距離 = フォアとバック（両手・片手）は選手の見た目のデータの値（仮の男性はフォア 0.82 m／バック 0.62 m）、ボレー 0.80 m、スマッシュ 0.25 m
前の距離 = 選手の見た目のデータの値（仮の男性は 0.38 m。体の前で打つ）
```

フォアとバックの横の距離と前の距離は、選手の見た目のデータ（§7 の `ReachBody`）が持つ：その体で焼いたスイートスポット（§7 の `StrokeFits`）のうち、中くらいの高さのグラウンドストローク（打点の高さ 1.0 m：§5.3 の高さの変種では上の行）で選ばれるストロークの横の位置と、前の位置の平均（フォア・片手のバック・両手のバックの 3 つの入力ごとの平均。[パラメータ表](../05_Data/02_Parameter_Tables.md) §4.1。T-STRK-011）。選手は見た目を付けるときに、探索の値（`FReachParams`）に入れる。見た目のデータに値がなければ、警告を出してパラメータ表の既定を使う（探索の見積もりにだけ効き、体の目標はストロークが決まった後にその体の値で置き直す：§6.2）。合わないと、ストロークが決まった後に体の目標を置き直すときに、探索の到達の見積もりが狂う。M3 は、ボレー・スマッシュの候補もフォアとバックの仮のストロークで振る（§5.3）ので、前の距離はどの種類にも同じ値を使う（種類ごとの値は、そのストロークを入れる M9 で見直す）。

フォアかバックかは、ボールの軌道が体のどちら側を通るかと、利き手で決める。体の正面に近い（横 0.3 m 未満）場合は、回り込む時間があれば（フォアが得意な選手は回り込みを優先する）フォア、なければバック。

### 4.4 計算の置き場所と型

探索は TennisSim の `TennisReach`（`TennisSim/Public/Reach/TennisReach.h`。Engine に依存しない純粋な関数）で行う。`UTennisReachComponent` は、ボールの予測軌道（`UTennisBallSimComponent`）と選手の位置・速度（コート局所の m）を集めて呼ぶだけにする（移動の `TennisMovement` と同じ分け方。テストと決定論のため）。

| 型・関数 | 内容 |
|---|---|
| `FReachQuery` | 探索する選手：位置・速度（XY）、初動ブーストの残り、側（SideSign）、利き手、バックハンドの打ち方、探索の開始時刻 Now、反応の時間、準備の時間 |
| `FReachParams` | 帯・距離・重みなどの値（§4.5。USTRUCT。既定は DATA-02 §4.1） |
| `FHitCandidate` | 候補：時刻 Time、ボールの位置・速度、体の目標位置（XY）、フォア／バック（`EStrokeSide`）、種類（`EHitKind`：Groundstroke・Volley・HalfVolley・Smash）、ストレッチか、到達時間 t_req、点数 |
| `TennisReach::TimeToReach` | §4.1 の到達時間。移動の値（`FMovementParams`）をそのまま使い、移動のモデル（`TennisMovement::Step`）と同じ規則で、目標の向きの成分だけを見る（加速・最高速度・後退・ブースト）。目標と逆向きの速度は、方向転換の損失（`TurnKeep`）の後に加速で向きを変える。最高速度を超えていれば Brake で落とす。到着の速さは問わない（止まる時間を含まない） |
| `TennisReach::FindCandidates` | ACT-03。予測軌道のサンプル（240 Hz）をすべて調べ、候補を点数の降順（同点は早い順）で返す |

- 時刻は予測軌道と同じシミュレーションの時刻。Now より前のサンプルと、選手の範囲（§2.4）の外に体の目標位置が出るサンプルは捨てる
- 反応の時間は、プレイヤー 0 s（人は自分で反応する）、AI は難易度の値（DD-05）。準備の時間は、ストロークの `WindupTime`（W-3.4 まではパラメータの既定）
- 候補が 1 つ以上あれば、選手は入力に「打点の候補が見つかった」と知らせる（ST-05。押した瞬間に見つかった場合も同じ）。見つかるまでは毎フレーム探す（1 回 0.2 ms 未満：T-STRK-001）ので、ボールが打たれて予測軌道が変わった場合も、選手が動いて間に合うようになった場合も拾える
- 探索のコンポーネントはボールのシミュレーションの後に処理する（ARCH-01 §5。`ATennisCharacter::FollowBall`）

### 4.5 候補の種類とフォア・バック

| 種類 | 条件（ボールの中心の高さ z、自分の側のサンプル） | 横の距離 |
|---|---|---|
| Groundstroke | 1 回バウンドした後、z が 0.25〜1.7 m | フォアとバック（両手・片手）の値（§4.2。見た目のデータ） |
| HalfVolley | 1 回バウンドした後 0.15 s 以内、z ≤ 0.35 m（Groundstroke より優先） | Groundstroke と同じ |
| Volley | バウンドの前、z が 0.3〜2.2 m | 0.80 m |
| Smash | z が 2.2〜3.2 m（バウンドの前後どちらも） | 0.25 m |

- 横の向き：ボールが選手から見て右（ネットの方を向いて右）にあり右利きならフォア。左利きは逆。打点と今の位置の横の差が 0.3 m 未満なら、まずフォアを試し、間に合わなければバックにする（回り込み）
- 2 回目のバウンドより後のサンプルは使わない
- ストレッチ：間に合わないが、使える時間で目標位置まで残り 0.6 m 以内に近づけるなら、ストレッチの候補にする（体勢の点 0、点数 ×0.5）
- 高さの点：0.8〜1.2 m で 1。帯の端で 0 まで線形に下げる（Smash は帯の中で 1）。前で取る・移動の少なさは、その探索の候補の中で正規化する（最も早い・最も近いが 1）

## 6. アニメーションの同期

### 6.1 時刻合わせ

```
T_hit  = 打点の候補の時刻（予測軌道）
T_now  = 現在のシミュレーション時刻
avail  = T_hit − T_now
PlayRate = clamp(ImpactTime / avail, 0.80, 1.25)
if ImpactTime / avail > 1.25:   StartPosition = ImpactTime − avail × 1.25   … 途中から再生（テイクバックを省略）
if ImpactTime / avail < 0.80:   開始を遅らせる（avail − ImpactTime/0.80 だけ待ってから再生）
```

再生中も、0.05 s ごとに `T_hit` を予測軌道から読み直し、PlayRate を少しずつ（1 秒あたり ±0.5 まで）補正する（ネットワークの補正・風に対応する）。M3 は、打ち出しの後に予測が変わらないので、`T_hit` は始めたときの値のまま使う（`UTennisStrokeComponent`。読み直すのは、予測が変わる仕組み（ネットワークの補正）を足すとき）。

| 項目 | 内容 |
|---|---|
| 時計 | `T_hit`・`T_now` は、ボールのシミュレーション時刻（`UTennisBallSimComponent::GetState().Time`。打点の候補の時刻と同じ時計）。入力の時刻（ワールドの秒：ST-05）とは混ぜない。ストロークの進行は、ボールと同じ固定の刻みで進める：ボールのコンポーネントが数えるステップの通し番号（`UTennisBallSimComponent::GetStepCount`。[DD-01 §3.3](01_BallPhysics_Detail.md)）を、始めたときと毎フレーム読み、前に読んだ番号との差のステップ数だけ進める（`TennisStrokeStep::Advance` の `NumSteps`）。ボールが飛んでいる間は、`T_hit` までの残りが、進めたステップ数 × `SimDt` だけちょうど減るので、インパクトの時刻 T がボールの時刻の上でずれない（別々の時計だと、フレームごとのステップ数が 1 ずれて、T が最大 1 ステップずれる）。通し番号は、ボールが飛んでいない間も進む（ボールの状態と時刻は飛んでいる間だけ進む）ので、ボールが止まっても、ストロークは終わりまで進む。どちらを先に Tick しても、番号の差で数えるので同じ（利用者の判断、2026-11-14。それまでは「自分の固定の刻み」） |
| 始める時点 | 打点の候補が見つかり、ストロークを選んだとき（予約。[操作仕様 §4.1](../01_Specification/04_Controls_Specification.md) の「テイクバックを始める」）。ボタンを離す時刻は、品質にだけ効く（振りの開始は変えない） |
| 計算の置き場所 | TennisSim の純粋な関数（`TennisStrokeTiming`：始め方の計画 `PlanStart`＝待つ時間・開始位置・再生速度、再生中の補正 `CorrectPlayRate`、体の向き `FacingYaw`（rad）、体の目標位置 `BodyTarget`。T-STRK-012）。値は [パラメータ表](../05_Data/02_Parameter_Tables.md) §4.2。`UTennisStrokeComponent` は結果をモンタージュに渡すだけ |
| `avail` ≤ 0 | 候補の時刻を過ぎている：開始位置をインパクトの時刻にし、再生速度は上限（遅れて振る。インパクトの判定で空振りになる） |

`PlayRate` はステッパの中だけで使う（モンタージュの位置を進める速さ）。モンタージュそのものは止めておき（`Montage_Pause`）、毎フレーム、ステッパの位置を置く（`Montage_SetPosition`。§6.6）ので、アニメの更新の時間・`RateScale`・時間の倍率は、インパクトの時刻に効かない。`RateScale` は 1 にそろえる（`StrokeMetaBaker` が検査する。RES-06 G-9）。

### 6.2 位置合わせ（移動のモデルで体を運ぶ）

ストロークのモンタージュは**その場で**再生し（ルートを動かさない）、体は移動のモデル（`TennisMovement`）の自動移動（§2.3）で打点へ運ぶ。Motion Warping は使わない（利用者の判断、2026-11-12。[RES-06](../00_Research/06_UE58_Animation_Stroke_API.md) §6 G-1 の案 B）。

| 項目 | 内容 |
|---|---|
| 理由 | root motion のモンタージュの間は、CMC が `CalcVelocity` を呼ばず、`TennisMovement` が効かない（RES-06 G-1）。その場のモンタージュなら、ストロークの間も移動のモデルは 1 つのままで、結果を再現しやすく、ネットワーク（M8）とリプレイで同じ計算になる。左利きのミラーもそのまま使える（G-8）。Beta の Motion Warping に、コードが依存しない |
| 体の目標位置 | `BallPos(T_hit) − Rotate(Yaw, スイートスポットの位置)` の水平の成分（Yaw は、インパクトのときの体の向き。スイートスポットは、そのストロークの選手の見た目のデータの焼いた値（§7））。`SetAutoMoveTarget(目標位置, 残りの時間, 止まっていたい時間)`（§2.3）で向かう。打点の探索の `BodyTarget`（§4.2）と同じ式で、ストロークが決まった後は、そのストロークのスイートスポットで置き直す |
| 体の向き | 打球方向（狙いの方向）へ回す。ただし、ネットの方向から ±35° まで。インパクトまでに回し終える。狙いの方向は、打点から狙いの地点へ（M3 はニュートラルの狙い：§6.4。M4 から `FShotIntent` の狙い） |
| 打点の選び直し | ストロークが決まったら、打点の時刻を、ボールの高さが**そのストロークのスイートスポットの高さ**（選手の見た目のデータの焼いた値（§7）の Z）にいちばん近い時刻に選び直す（利用者の判断、2026-11-13）。探す範囲は、候補の時刻の前後 0.25 s のうち、今より後・同じバウンドの間・自分の側・候補と同じ種類の高さの帯の中で、その時刻の体の目標が移動の範囲（§2.4）の中にあり、間に合う（探索と同じ到達時間の式。ストレッチにしない）サンプル。候補より高さの遠いサンプルは選ばない。なければ候補のまま。点数は探索のときのまま。理由：探索は 0.8〜1.2 m を同じ点数で扱うので、候補の高さは 0.70〜1.27 m にばらつき、スイートスポットの高さ（仮のストロークで 1.02・1.08 m）との差が平均 14.7 cm ある（シードを決めた 1,000 球の計測、2026-11-13）。体の位置は水平にしか合わせられないので、そのままでは T-STRK-003 を満たせない。選び直すと、高さの差は平均 3.0 cm（中央値 0.3 cm）になる。計算は TennisSim の純粋な関数 `TennisReach::RefineForStroke`（体の目標は `TennisStrokeTiming::FacingYaw`・`BodyTarget` で、狙いへの向きを入れて置く。T-STRK-013）。到達の条件を入れた実際の関数では、300 球で 15.0 → 3.6 cm |
| 残り | 体が目標に届かない分は、腕の微調整（§6.3。最大 0.12 m）で埋める。それより大きければ、インパクトの判定（§6.4）の距離で、当たり方が決まる |
| 呼び出し | 候補が見つかったときに、`ATennisCharacter::HandleCandidateFound` が、先に入力へ知らせ（バッファ → 溜め中）、それから `UTennisStrokeComponent::PlayStroke()` を呼ぶ。この 1 か所で、ストロークの選択・打点の選び直し・自動移動の目標（そのストロークのスイートスポットで置き直す）・モンタージュの再生・体の向きを決める。スイートスポットは、選手が付けている見た目のデータ（`ATennisCharacter::GetAppearance`）から、選んだストロークの焼いた値を引く。選べない・その見た目のデータにそのストロークの焼いた値がない・始められないなら、選手はストロークを終える（入力は溜め中から待機へ）。インパクトは `OnStrokeImpact` で入力に知らせ（離した → 確定）、RecoverStart で `OnStrokeEnded`。離した意図は記録するだけ（振っていなければすぐ終える） |
| モンタージュ | root motion を持たない（アセットの Root Motion をオフにし、`StrokeMetaBaker` が、ルートの骨が動いていないことを検査する） |
| 弱点と対策 | 振っている間に体が動くと、足が滑って見えることがある。テイクバックの間は下半身を Motion Matching にし（§6.5）、歩幅は Stride Warping で合わせる。見た目の仕上げは M9（モーションキャプチャ）で見直す（[リスク表](../09_Project/02_Risk_Register.md) R-06） |
| 固定の刻み | 移動は固定の刻みで進める（§2.2。W-3.5 で、CMC の `DeltaTime` で 1 回進める形から変えた：RES-06 G-1） |

### 6.3 腕の微調整（Control Rig）

- インパクトの 0.15 s 前から 0.05 s 後まで、`CR_TennisPlayer` の Full Body IK で、利き手（ラケットのグリップ）を、位置合わせの残り（§6.2 の「残り」：スイートスポットとボールの差。高さの差を含む）の分だけ動かす（最大 0.12 m）。作るのは M9（本番のストロークと一緒に。M3 では作らない：§12.1）
- 両手バックハンドでは、もう一方の手をグリップのソケットに吸着させる（常時）
- 足：Foot IK（地面との接地）。ストローク中は踏み込む足の位置を固定する

### 6.4 インパクトの判定

1. インパクトの時刻は、ストロークの進行（§6.6：モンタージュの位置を固定の刻みで積分する）が、焼いた `ImpactTime` を越えた時刻 T。Notify「Tennis Impact」はモンタージュの上の目印で（`StrokeMetaBaker` が時刻を読む）、実行時の合図には使わない：Notify の発火はフレームの単位で、ボールの処理との順にも左右されるため
2. T は、越えたステップの中での位置から、ステップの端数まで求める（`T = そのステップの終わりの時刻 − (位置 − ImpactTime) / 再生速度`）。フレームの分け方によらない
3. ボールの状態 = `BallSim->GetStateAt(T)`。スイートスポット = T の体の位置と向きに、そのストロークの選手の見た目のデータの焼いた値（§7）を足した位置（計算で求める。利用者の判断、2026-11-13）。インパクトの前後でラケットは 60 fps の 1 フレームに約 9 cm 動くので、フレームの骨の位置を使うと、フレームのタイミングだけで数 cm ずれる。焼いた値が Slot で再生した姿勢と 1 cm 以内で合うことは T-STRK-010 が確かめている
4. 距離 ≤ `FStrokeSyncParams::ImpactReach`（0.25 m：パラメータ表 §4.2）なら打球（[ACT-04](../03_UML/05_Activity_Diagrams.md)）。それより遠ければ空振り：打ち出さず、ストロークは最後まで振る。距離はログに出す（`[Stroke] <選手>: impact distance=… hit=…`。T-STRK-003 の計測は同じ値を使う）
5. **T の体の位置と向き**：選手の移動は、ボールとストロークの後に動く（Tick の順：§6.6）ので、インパクトを知った時点の選手の位置は、このフレームの始まりの位置。T の体の位置 = その位置 + 選手の速度 ×（T − このフレームの始まりのボールの時刻）（フレームの中の速度の変化は無視できる：加速度 10 m/s² でも 2 mm）。体の向きは `FStrokeStepper::TargetYaw`（ステッパはインパクトでちょうどそこに着く。§6.6）。スイートスポットは、地面の上の体の位置から、向きで回した焼いた値の前と横（横は利き手で反転）と、焼いた値の高さ。打点の選び直しの体の位置（`TennisStrokeTiming::BodyTarget`）のちょうど逆の計算（`TennisSim` の関数。往復の単体テスト）。コート局所の m で計算し、ワールドとの変換は `ATennisCourt` だけ
6. **打球**（4 で打つとき）：打点は T のボールの位置（`GetStateAt(T)` の `Pos`。スイートスポットではない：ボールを最大 0.25 m 瞬間移動させない）、狙いはニュートラルの狙い（`TennisStrokeTiming::NeutralAim`：体の向きと同じ）。球種のデータは、設定（`UTennisPlayerSettings::ShotTypes`）の `DA_Shot_*` から、押した球種（`FShotIntent::Type`）と同じ `Type` のものを選ぶ。溜めは（離した時刻 − 溜めの始まり）÷ そのストロークの `ChargeTime`（`UStrokeData`。操作仕様 §4.1 の表）を 0〜1 に収めたもの。押したまま（`bAutoReleased`）なら 1（ST-05。利用者の判断、2026-11-14）。どちらの時刻もワールドの秒なので、比は時計によらない。利き手は右、横の入力は 0（M4 で入力から）。`TennisShotRequestMapping::Make` → `FTennisShotSolver::Solve` → `UTennisBallSimComponent::Launch`（打ち出しの時刻は T。T は今より前なので、`Launch` が今まで早送りする：DD-01 §3.4）。ソルバが `Nearest`（`bSolved = false`。DD-02 §7.4）で返しても打ち出して警告を出す（物理的に無理な打球として扱う：DD-02 の演出の表）
7. **打てないとき**：T のボールの状態が求まらない（`GetStateAt` が false）、押した球種のデータが設定にない、ときは打ち出さず、警告を出して空振りと同じに扱う（ストロークは最後まで振る）
8. **順**：意図（球種・溜め）を読む → 判定 → 打球 → 入力に知らせる（`ATennisCharacter::OnStrokeImpact` → `Impact`。空振りでも知らせる：入力が確定に進む）。知らせを受けた入力が意図を取り消すことがある（ST-05）ので、知らせるのは最後。打った選手の記録（DD-01 §6 のイベントの打者、DD-04 §3.1 の `LastHitter`）は、読む側（ルールの判定）を作るときに足す（今は読む処理がない）

**M3 の打球**（利用者の判断、2026-11-13）：狙い（W-4.2）と品質・誤差（W-4.1）ができるまで、打球では、押した球種のデータ（`DA_Shot_*`）の既定の値で、ニュートラルの狙い（[操作仕様 §4.3](../01_Specification/04_Controls_Specification.md)：相手のコートの中央、ネットから 9.0 m）へ、誤差なしで打ち出す（`FTennisShotSolver::Solve` → `UTennisBallSimComponent::Launch`。打ち出しの時刻は T）。M4 で、狙いと誤差を入れた着地点に置き換える。

### 6.6 ストロークの流れと終わり（`UTennisStrokeComponent`）

| 項目 | 内容 |
|---|---|
| 始まり | 打点の候補が見つかったとき（`ATennisCharacter::HandleCandidateFound`）に、ストロークを選び（§5.3 の `Select`）、`PlayStroke` で再生を計画する（§6.1）。選べなければ（表に結果がない）、または選手の見た目のデータにそのストロークの焼いた値がなければ、警告を出してストロークを終える |
| 状態（`EStrokeState`） | None（振っていない）／Waiting（開始を遅らせている）／Swinging（再生中。インパクトの前）／FollowThrough（インパクトから RecoverStart まで） |
| 自動の離し | ボタンを離さないままインパクトが来たら、入力はそこで離したことにする（ST-05：溜め中 → 確定。判定は `t* + W_late` に離したもの＝Late の端、溜めは最大。利用者の判断、2026-11-14：`ReleaseLeadTime` ≤ 0.15 s < `W_late` なので、`t* + W_late` はいつもインパクトより後。ショットはインパクトで決まる）。`t* = T_hit − ReleaseLeadTime`（ボールの時刻。`ReleaseLeadTime` は `UStrokeData` の手動の値：§5.2）。`W_late` は Early／Late の窓の端（0.200 s：パラメータ表 §5。利用者の判断、2026-11-13） |
| 進め方 | TennisSim のステッパ（`TennisStrokeStep::Begin`・`Advance`・`Cancel`。状態 `FStrokeStepper`＝状態・待つ時間・モンタージュの位置・再生速度・体の向き。T-STRK-014）を固定の刻みで進め、インパクト（時刻 T。`Advance` の終わりの時刻の `ImpactLead` 秒前で、ステップの端数まで求める）と終わりを出来事として返す。`Advance` には、進めた後の「打点の時刻 − ボールの時刻」を渡す。Waiting の間は `ReplanInterval` ごとに `PlanStart` で計画し直し、Swinging の間は `CorrectPlayRate` で再生速度を補正する（§6.1）。打点の時刻を過ぎてから始めたときは、インパクトの位置から再生し、最初のステップでインパクトを 1 回出す。読み直しの間隔は `ReplanInterval` をステップ数に丸めて数える（0.05 s は 12 ステップ。時間を足し合わせると誤差で 1 ステップずれる）。ステッパは、ボールのステップの通し番号の差だけ進める（§6.1 の「時計」。各ステップの「打点の時刻 − ボールの時刻」を逆算するため）。この前提の下で、結果はフレームの分け方によらない。インパクトの時刻 T の体の向きは計画の向き（`TargetYaw`。`Advance` が返った時点の向きは、もうネットへ戻り始めている）。`UTennisStrokeComponent` は、毎フレーム、ステッパの位置を、止めたモンタージュに置くだけ（`Montage_Pause` と `Montage_SetPosition`。アニメの更新では進めないので、フレームの時間・時間の倍率 `tennis.TimeScale` によらず、ステッパの位置の姿勢になる。止めたままでも、Slot の重みは重ね始めの時間で重なる：`Tennis.Game.Stroke.TennisStrokeMontage`）。RecoverStart の後は、止めるのをやめて最後まで再生する。Tick はボールの後、移動とメッシュはストロークの後（`ATennisCharacter::FollowBall`）。T-STRK-015。体の向きは、始めの向きから計画の向き（§6.2）へ、インパクトの時刻にちょうど着くようにステップごとに回し、インパクトの後は RecoverStart までにネットの方向へ戻す |
| フォロースルー | インパクトで自動移動（§2.3）を止める。インパクトから RecoverStart まで（`FollowThroughLock`）、移動の最高速度を ×0.40 にする（§2.1。`UTennisMovementComponent::SetFollowThrough` で `FMovementModifiers::bFollowThrough` を付け外しする）。制限は、インパクト・RecoverStart を見つけたフレームのすべてのステップに効く（フレームの単位。インパクトの時刻 T のステップからではない。§2.2 の入力と同じ扱い。利用者の判断、2026-11-14。ステップの単位にするのは、オンライン v1.1 で移動の状態を見直すとき） |
| 終わり | Notify「Tennis Recover Start」の時刻に、`OnStrokeEnded` を知らせる（入力は待機に戻り、次のボタンを受け付ける。利用者の判断、2026-11-13）。空振りも同じ。モンタージュは最後まで再生する（構えに戻る） |
| 取り消し | 入力が取り消されたら（`CancelShotIntent`）、自動移動を止め、インパクトの前ならモンタージュを止める。インパクトの後は、そのまま終わりまで進める（ステッパの `Cancel` は、インパクトの前だけ取り消して true を返す。インパクトの後は false を返し、終わりを出すまで進める）。取り消した後の体の向きは、ネットの方向へ `ReturnYawRateDeg` で戻す（§6.5）。振っている途中（インパクトの前でも後でも）で次のストロークを始めたら、前のものは知らせずに打ち切り、フォロースルーの制限を外してから始める（`UTennisStrokeComponent::PlayStroke`。新しいモンタージュを再生できなければ、前のものはそのまま）。振っている途中にボール・移動がなくなったら、警告を出して打ち切り、終わりを知らせる。インパクトの後に取り消したストロークは、RecoverStart まで進むが `OnStrokeEnded` を知らせず（入力は取り消しで待機に戻っている）、押し直した次の予約（バッファ中の探索）も消さない（`ATennisCharacter::HandleStrokeFinished`） |

## 11. リカバリー

- 打った後、相手が打てる範囲（相手の打点から、自分の側のシングルスコートの両端への 2 本の線）の**角の二等分線上**で、ベースラインから `RecoverDepth` 後ろの点へ戻る

- プレイヤーの場合、リカバリーは手動の移動（アシストがあれば、移動のアシストの理想点として使う）
