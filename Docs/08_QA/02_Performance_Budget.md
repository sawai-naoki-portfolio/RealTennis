## 2. 最低環境（1080p、品質「低」、TSR で 66% の内部解像度）

| 項目 | 方針 |
|---|---|
| GI | Lumen Lite または なし（事前計算の空の光） |
| 影 | VSM の解像度を下げる／シャドウマップ |
| 観客 | 近景の観客なし。カードの数を 1/2 |
| 服 | Cloth なし |
| 目標 | 平均 60 fps、1% Low 45 fps（NFR-PERF-002） |

## 4. 読み込みとヒッチ

| 項目 | 予算 | 対策 |
|---|---|---|
| 試合の開始（SSD） | 15 s 以内（NFR-PERF-008） | 会場のレベルの非同期読み込み。ショット表はキャッシュ（初回のみ作成） |
| ヒッチ（> 50 ms） | 1 試合で 0 回（NFR-PERF-010） | PSO の事前キャッシュ、シェーダーの事前コンパイル、GC を試合中に走らせない（ポイント間にまとめて行う） |
| 入力の遅延 | 3 フレーム以内（NFR-PERF-004） | 入力 → 予約の処理を同じフレームで。描画のバッファを増やさない |

## 5. 計測の方法

| 道具 | 使い方 |
|---|---|
| `stat unit`／`stat unitgraph` | 開発中の目安 |
| Unreal Insights | 予算を超えた処理の特定（`TRACE_CPUPROFILER_EVENT_SCOPE` を TennisSim の主要な関数に入れる） |
| CSV Profiler | 自動の計測（`-csvprofile`）。L4 の性能テストで、AI 対 AI の試合を描画ありで実行し、フレーム時間の分布を記録する |
| Gauntlet | 決まった手順（入場 → 3 ゲーム → リプレイ → 終了）を自動で実行して計測する |
| `memreport -full` | メモリの内訳 |

### 5.1 合否

| 指標 | 合格 |
|---|---|
| 平均のフレーム時間 | ≤ 16.67 ms |
| 1% Low | 推奨 ≥ 50 fps、最低 ≥ 45 fps |
| ゲームスレッドの P99 | ≤ 12 ms |
| 50 ms を超えるフレーム | 0 |

## 6. 予算の管理

- 予算を超える変更を入れる PR では、計測の結果（変更の前と後）を PR に貼る
- 予算の配分を変える場合は、この文書を更新する PR を先に出す
- スマートフォンの予算は M10 の開始時に定める（端末の選定と合わせて）
