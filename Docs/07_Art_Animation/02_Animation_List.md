## 1. 命名

```
AM_<種類>_<高さ>_<ファミリー>_<スタンス・到達>[_<変種>]
  種類：FH（フォア）、BH1（片手バック）、BH2（両手バック）、VO（ボレー）、HV（ハーフボレー）、SM（スマッシュ）、SV（サーブ）、RT（リターンのブロック）
  高さ：VLow / Low / Mid / High / Over
  ファミリー：Drive / Slice / Lob / Drop / Block
  スタンス・到達：Open / Semi / Square / Closed / Stretch / Dive / Slide
例：AM_FH_Mid_Drive_Open、AM_BH2_Low_Slice_Stretch、AM_SV_Over_Kick
```

- 変種 `Dip`：同じ高さの帯の中の低い打点を、腰を落として打つ（M3 の仮のストローク。打点の高さの範囲の列で選ぶ：DD-03 §5.3。例：`AM_FH_Mid_Drive_Square_Dip`）

- **その場で**作る（ルートの骨を動かさない。体は移動のモデルが運ぶ：[DD-03 §6.2](../04_DetailedDesign/03_Player_Movement_Stroke_Detail.md)）。収録で動いた分は、後処理でルートから抜く
- 30 fps で収録・書き出し。左利きはミラー（Mirror Data Table）で作り、個別には作らない
- フレーム数の目安：テイクバック 12〜20、スイング 6〜9、フォロースルー 15〜25

## 5. Notify の規則（全ストローク共通）

| Notify | 種類 | 位置 | 用途 |
|---|---|---|---|
| `Impact` | `UAnimNotify_TennisImpact` | ラケットがボールに当たるフレーム | インパクトの判定（必須） |
| `SwingWindow` | Notify State | スイングの開始 〜 インパクト | 球種の変更の締め切り、IK の有効化 |
| `RecoverStart` | `UAnimNotify_TennisRecoverStart` | フォロースルーで移動を始められるフレーム | `FollowThroughLock` の自動計算 |
| `Footstep_L/R` | Notify | 足の接地 | 足音・スライドの判定 |
| `Grunt` | Notify | インパクトの直前 | 選手の声 |

- `StrokeMetaBaker`（エディタのツール）は、`Impact` の時刻と、そのときのスイートスポットの位置を読み、`UStrokeData` に書く。`racket_sweetspot` は骨格ではなくラケット `SM_Racket` のソケットなので、手のソケット `racket_attach_r` × ラケットの `grip` の逆 × `racket_sweetspot` を合成する（空間と基準は [DD-03 §5.2](../04_DetailedDesign/03_Player_Movement_Stroke_Detail.md)）。ソケットの名前がなければエラーにする（黙って 0 にしない）（FR-STRK-007）
- Notify が足りない・順序がおかしいモンタージュは、ツールがエラーにする

## 6. 収録の計画

| 項目 | 内容 |
|---|---|
| 方法 | 光学式または慣性式のモーションキャプチャ（Rokoko・Move.ai など）。経験者（コーチ級）を被写体にする |
| ラケット | 実物のラケットにマーカー（またはセンサー）を付け、インパクトのフレームを音で同期する |
| ボール | 実際に球出しを打つ（打点の高さを 5 段階に分けて収録） |
| 後処理 | IK Retargeter で Manny 互換の骨格へ。足の滑りの除去（Foot Lock）。インパクトのフレームに `Impact` を打つ |
| 検証 | 運動連鎖の順序（脚 → 腰 → 体幹 → 肩 → 腕）を、骨の角速度のピークの順で確認する（[RES-03 §5](../00_Research/03_Player_Match_Stats_Research.md)） |
